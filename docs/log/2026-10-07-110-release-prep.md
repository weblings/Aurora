# 1.1.0 release prep: audit, bump, docs, Aurora-07i, vendor sequencing

Id: 110-release-prep

2026-10-07. Owner asked for an audit of everything since `v1.0.4` ahead of a
release, and chose 1.1.0 over 1.0.5 (new Pause/Resume, error shell, new
`/api/state` routes, CLI flags, shared core runtime).

## Done

- Version 1.1.0 in `CMakeLists.txt` and `web/demo/demo-shim.js`. Owner
  wrote the `CHANGELOG.txt` entry. `demo-shim.test.mjs` passes.
- Docs (Aurora-kil1): root README drops "Mac is experimental", lists
  Pause / Resume and See Error, adds Troubleshooting for Wayland
  (`AURORA_PW_DMABUF=0`) and a denied Mac Local Network prompt. App READMEs
  list tray items and describe the `PipelineHost` loop (was
  `Orchestrator::update()`). `web/ui/README.md` says what `shell.js` owns.
- Aurora-07i closed: `sendHttpRequest` takes a per-call `timeoutMs`
  (default 1000), discovery.meethue.com gets 5000. Hue tests 48/48 on
  Windows. Full app link blocked by a running `Aurora.exe` (LNK1104), so
  the first-click Autodetect check was not run.
- Aurora-9swq closed by owner (copy fix in HEAD, Mac checks confirmed).
- Aurora-4jl revised by owner: the demo fork becomes a sync target. Sequenced
  as Aurora-ifkn.1-6 (move each seam upstream), .7 (sync script and
  re-vendor), .8 (byte-equality CI test, docs, Pages publish). The vendor
  dir stays inside `web/demo` so the subtree push keeps working.
