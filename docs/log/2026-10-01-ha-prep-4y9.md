# Aurora-4y9: output-neutral NUX probe table in web/ui/app.js

Id: ha-prep-4y9

Item 3 of [[home-assistant-output]]'s prep work. Acceptance criteria met (see
Verification); bead closed.

## Change

- `OUTPUTS` table in `web/ui/app.js`, one entry (`hue`): `probe()` returns
  `{ needsConnect, needsSelect }`; `stages.connect({ platform, next })` holds
  the Welcome -> Mac tip -> Output Connect chain, `stages.select({
  previousStep, next })` the entertainment zone select. Both moved verbatim.
- `probeState()` picks the first `capabilities.outputs` name the table knows
  (none = no output stages, as when Hue was absent) and returns `output`,
  `needsOutputConnect`, `needsOutputSelect`. `goToEntertainmentZoneSelectStage`
  became `goToOutputSelectStage`. Only comments in `bootstrap` still mention
  the bridge.
- `styles/mac-tray-tip.test.mjs` asserts on `app.js` source text; its
  `state.platform === 'mac'` check now looks for `const isMac = platform ===
  'mac'`.

## Verification

- Trace comparison: HEAD `app.js` vs the working copy, each run against stub
  screens and a faked `fetch`: 641 scenarios (platform, outputs list incl.
  none/absent/unknown-first, connection states incl. failure, config, zones,
  capabilities failure) x 4 walks (forward; Back at depth 1-3). 5,128 trace
  lines byte-identical, 37 distinct flows. Two deliberate breaks (hard-coded
  `isMac`, dropped `configured &&`) were both caught.
- Browser (headless Chromium, `--fake-hue --fresh` app, per-scenario restart,
  old copy served via `AURORA_WEBUI_DIR`): five states (fresh, paired without
  zone, paired with zone, mode set, nux completed) land on the same first
  screen, no page errors. Fresh-install click-through (Welcome -> zone select
  -> Mode+Device -> Zone Mapping -> Back -> Dashboard) identical in 4/4 runs
  with event-driven waits.
- Paired-without-zone click-through varies run to run, old vs old included
  (one old run went straight to the Dashboard, another stopped at Zone
  Mapping); every new-code outcome also occurred with old code. Cause not
  investigated (suspected timing of zone state).
- Mac (2026-10-01): `web/ui` node tests 7/7, including `mac-tray-tip.test.mjs`.
  The trace compare already varied `platform` (mac included), so the
  Welcome -> Mac tip -> Output Connect chain was compared without a Mac. No
  live Mac click-through.
- Not run: Windows.

## Findings

- A fixed 1.8s wait after each click produced a false "new code stalls"
  signal; waiting for the screen to change removed it.
- A wait loop `until ! pgrep -f "node x"` matched its own shell and hung.
- Lessons: trace-compare for entry scripts (`web-testing`); control run and
  event-driven waits, pgrep self-match (`debugging-method`).
