## Real Hue bridge

The extracted zip, run from a new folder under `~/Applications` with `open` and
`AURORA_CONFIG_DIR` pointing at a copy of the owner's settings. Real screen
capture. Agent drove the API and read the area status; the owner watched.

| Step | App | Area, polled to 35 s | Owner saw |
|---|---|---|---|
| Screen colors | running | active | lights follow the screen |
| Input set to an unknown name (`d5n4`) | running, reload error | active | still following |
| Input restored, effect with an unknown node type (`5q5h`) | failed | active | stayed purple |
| Same effect selected again | failed | active | stayed purple |
| Screen colors | running, no errors | active (polled to 20 s) | following again |

After the run the app log held `Failure light on.` for each broken-effect
selection. The broken effect still stops the area just before the light's init
starts it; on this bridge that start was not discarded, unlike the report cited
in [[d5n4-inputs-before-outputs]]. The area was not read after the app exited.
