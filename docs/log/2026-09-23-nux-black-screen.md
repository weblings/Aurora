# NUX black-screen triage (PipeWire fraction, tick starvation, tray terminate, Continue busy)

Closed `Aurora-k7p`. Stuck-at-capture-source + refresh-to-black on Ubuntu 24.04/Wayland traced live against the user's box. Three stacked causes: (1) `PipewireGrabber::displayRefreshRate()` returned the raw `max_framerate.num` of an unreduced fraction -- 15729223 persisted as Hz via Orchestrator's derive-and-save; fix reduces `num/denom` (`denom == 0` means unset). (2) That rate (and the first 1000 clamp) starved `PipelineHost`'s tick mutex -- `tick()` holds it across grab+process+Hue stream, `sleep_until` in the past means no sleep -- so `/api/monitors` and `/api/zones` hung past 8s and bootstrap sat blank; fix clamps `setRefreshRate` and load-sanitize to the UI presets' top (240, measured sustainable here; 60 restored on the user's box), plus a 10s `fetchJson` timeout so a hung daemon shows unreachable+Retry. (3) Unrelated but found in the daemon log: `~TrayIcon` called `get_future()` on the already-moved promise, terminating on every shutdown; fix retrieves the future before the move (`Aurora-nzd`, fix committed).

Verification: core 65/65 (new garbage-load + clamp cases), input/linux 14/14, app/linux 14/14 (new tray construct/destroy case); endpoint timings at 1000/240/60 on hardware; `node --check` on UI edits; `check-lessons.sh` clean. PipeWire fraction itself has no committed test (ctor needs a live session); UI busy-state verified via throwaway jsdom harness in `/tmp` only.

Surprises/corrections: empty `activeMonitorName` is legitimate auto (red herring, lesson filed); the reasoned 1000 cap still wedged and was revised to measured 240 in a follow-up commit; rapid video->audio->video toggles only *looked* dead (silent 4.5s apply-await -- busy-state fix committed here for `Aurora-23a`); overlapping reloads survived fine.

Follow-ups: `Aurora-cgr` (tick debt-bounding -- any overrunning tick can still starve the mutex; 240 reload hung once here) and `Aurora-nzd` (tray fix committed earlier this stream) stay open; `Aurora-23a` keeps the busy-state verification note.
