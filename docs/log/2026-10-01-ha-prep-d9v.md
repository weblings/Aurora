# Aurora-d9v: httplib WebSocket client smoke test

Id: ha-prep-d9v

Item 5 of [[home-assistant-output]]'s prep work. Bead stays open: the Linux
half is done, the Windows (MSVC) and Mac runs are not.

## Change

- `core/tests/WebSocketSmokeTests.cpp`, added to `AuroraNetworkTests`: an
  in-process `httplib::Server::WebSocket("/echo")` on an ephemeral loopback
  port (no external echo process, no fixed port, so it runs unchanged on every
  platform) and an `httplib::ws::WebSocketClient` over `ws://`. Checks text,
  binary (embedded NULs) and a 256 KiB message echo, then a clean `close()`.
- wss:// untouched: needs httplib TLS, out of scope per the bead.

## Verification

- Linux (g++ 13.3, httplib 0.46.0 fetched): compiles, links, passes in 0.27s;
  full core suite 98/98 (was 97).
- Not run: Windows (MSVC), Mac. Run `cmake -S core -B build/core-tests`, build
  `AuroraNetworkTests`, `ctest -R WebSocket` there, then close the bead.
- Not proven: the test failing when it should (no deliberate break run).

## Findings

- httplib ships a ws server, so the "local echo server" the bead assumed is
  in-process; lesson in `web-testing` (also the shape for a fake HA server).
- `build/` (superbuild) has no core tests (app presets force `BUILD_TESTS`
  off); the test runs from `build/core-tests`. Already a `build-toolchain`
  lesson.
