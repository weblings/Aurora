# Aurora-a0r: output-neutral zone labels endpoint for Zone Mapping

Id: ha-prep-a0r

Item 4 of [[home-assistant-output]]'s prep work. Acceptance criteria met on
Linux; Windows and Mac `main.cpp` edits compile and link.

## Change

- `IOutput::zoneLabels()`: `map<zoneId, vector<name>>`, default empty. A zone
  missing from it renders as bare "Zone N".
- `HueOutput::zoneLabels()`: device names per channel of the already-selected
  entertainment config (no bridge call; empty before `init()`).
- `ZoneListResult` gained `labels`; each app's `listZones()` fills it from
  `m_outputPtrs.front()->zoneLabels()` (same first-output scope as zones).
- `GET /api/zones/labels` in `core/Runtime/src/ZoneRoutes.cpp` returns
  `{succeeded, labels:[{zoneId, names}]}`; empty list, not an error, with no
  live output.
- `ZoneMappingScreen.js` reads it instead of `/api/hue/channels`;
  `demo-shim.js` mocks it (+ shim test).
- `/api/hue/channels` kept: `DashboardScreen.js` and `ChannelList.js` still
  call it (bead named Zone Mapping only). `web/demo/vendor/webui` untouched
  (intentional fork).

## Verification

- Linux build, ctest 87/87, `demo-shim.test.mjs` passes; added a
  `zoneLabels().empty()` check in `HueOutputPluginTests`.

  `/api/hue/channels` returned the same four lamp names per zone. Real
  `ZoneMappingScreen` in headless Firefox showed "Zone 3 (Back Right Lamp)"
  etc. in both the zone dropdown and the Active zones list.

  ctest 70/70 (includes the `zoneLabels().empty()` check inside

  `GET /api/zones/labels` returned 200 with the four lamp names per zone
  (Front Left/Right, Back Left/Right), identical to `/api/hue/channels`.
  Browser render of `ZoneMappingScreen` not checked on Windows.
- Mac (Apple clang, `build/mac-app`): `aurora-app-mac` and `AuroraOutputHueTests`
