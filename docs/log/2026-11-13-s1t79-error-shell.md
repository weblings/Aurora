# Graph editor stage 6a: the Dashboard's error shell in the editor

Id: s1t79-error-shell

`Aurora-s1t7.9` (stage 6a, epic `Aurora-u68h`). The editor shows connection and host-state errors in the Dashboard's error shell, not its own banners. No core change; Grille stays on `0.1.0-dev.11`.

- **Component.** `web/graph-editor/src/ErrorShell.tsx`: `ShellBanner` (rows, collapsed "N problems" summary, Show less, light-test row) and `ErrorShell` (adds `#shell-banner-slot`, first element of `.editor`, and the "Aurora has stopped" takeover in `#shell-overlay-slot`). Props in, callbacks out, no fetch. It writes `shell.css` markup and imports `shell.css` plus `ui/messages.js`, `MacPermissionRecovery.js` (Mac permission, audio and Local Network rows are the Dashboard's own HTML, via `dangerouslySetInnerHTML`) and the new `ui/testHolder.js`. `editor.css` copies `.accordion-chevron` for the summary (dashboard.css is not loaded in the editor). `tsconfig` gained `allowJs` (no checking) so those modules type.
- **Markup test.** `ErrorShell.test.tsx` runs the real `web/ui/shell.js` `App` against a stub slot and compares its banner HTML with `renderToStaticMarkup(<ShellBanner/>)` for 13 cases (one row, paused host, `retry:false`, declined screen share, summary, expanded, condition, Mac permission, audio permission, agent test with clock, Live editor-tab test, test above a summary). Differences normalised: whitespace between tags, `style` spacing, `&#x27;`.
- **Rows from `GET /api/state`.** `useHostState.ts` reads it at once and every 3000 ms (abort 2500 ms, two failed polls in a row, single-flight), as `shell.js`. `graph/hostState.ts` holds the parse, the reachability rule (`reachAfter`) and the rest. Retry (`POST /api/reload`, or `PUT /api/state {running:true}` for `resume`), the dismiss X (`POST /api/state/dismiss`, running host with an `id`) and Stop test (`POST /api/graph/test/stop`) behave as the Dashboard's, each followed by a re-read.
- **One owner for reachable.** `useHostState`'s `reachable` drives the takeover and `pickStatus`'s rank 1 (Test button disabled, `data-preview` `Cannot reach Aurora`). A lost preview stream alone is no longer rank 1: it only asks the host poll to look (`useDraftLoop`'s `lookNow`). A failed draft PUT (network) does the same and is resent every 3 s; nothing is written into the shell for it. Takeover clears all rows, including editor-supplied ones.
- **Open failures.** A catalog or effect fetch that fails now asks the poll first: Aurora silent means the takeover (the load reruns on recovery, `recoveries`); Aurora answering means the existing `Cannot open '<id>'` / `Cannot reach Aurora: ...` banner with Retry, left for 6f.
- **Reload.** `Reload: <reason>` after Save is deleted (`App.tsx`, `WriteResult.reloadError`). A failed reload is in `/api/state` errors (`_recordFailure("reload", ...)`, `Pipeline.cpp`), so the shell shows "Couldn't apply settings: ..." or the running-host "Saved, but couldn't apply" row, as on the Dashboard.
- **Draft refusals by code** (`DraftRoutes.cpp`; `api.ts` `DraftRefused`, `graph/hostState.ts` `draftShellNote`, `graph/problems.ts`): 429 `too_many_drafts` is the row "Couldn't check your last edit: too many editors are open. Close one to continue."; 400 `invalid_session` / `invalid_body` (and any other refusal, e.g. an HTTP 500) is "Couldn't check your last edit."; 413 `draft_too_large` is a Whole graph problem on the chip, "Couldn't check your last edit: the graph is too large (over 256 KB)." (`draftIssues`, as 6e). No Retry, no X; `putError` clears on the next successful PUT. Rank 3 "Draft not sent" is gone from `pickStatus`; `summarize` no longer says it.
- **Light-test row, both pages.** `web/ui/testHolder.js` `testerName(holder)` ("an agent" / "another editor tab or window" / "another session") is shared by `shell.js` (new `lightTestHolder` from `/api/state` `test.holder`, "An agent is testing an effect on the lights." and so on; was "An MCP client ...") and the editor's `describeTest`. `/api/state` already carries `test.holder {session, client}`, so no core change. The editor hides the row when `holder.session` is its own tab session (`otherTest`).
- **Not done / left.** `pickBanner` and `.editor-banner` stay for 6f (Restore, the open-failure banner, rank 6 test/write text). Pairing-request rows (`/api/pairing/pending`, not `/api/state`) are not in the editor shell. The Test button's `Take over` still comes from `useLightTest`'s own 3 s holder poll (6c). `web/demo` vendors `shell.css` only; it is unchanged, and `shell.js` and `testHolder.js` are not vendored, so no demo resync.
