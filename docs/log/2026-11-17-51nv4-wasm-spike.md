# WASM spike: built-in graphs match native under Emscripten

Id: 51nv4-wasm-spike

`Aurora-51nv.4`. Go for the WASM evaluator, recorded on `Aurora-51nv`. `tools/wasm-spike/` builds the graph code plus a driver both native (MSVC, vcpkg) and with Emscripten 7.0.0 (OpenCV 4.12 core and imgproc, aubio from the vcpkg-pinned source with its built-in FFT, `-fexceptions`, `-msimd128`). Both run `builtin.video` (30 frames of fixed 64x32 RGBA) and `builtin.audio` (240 ticks of fixed 48 kHz PCM, `fixedAnchorHue` 30 so `palette.randomAnchor` is skipped) and print every frame. The graph links with no HTTP, network or store code. `ControlDescriptors.cpp` was left out because it includes `HttpServer.hpp`. The README lists the source set for `Aurora-51nv.5`. Background: [[sequence-e-research]].

## Verification
- `compare.py` native vs WASM: video 360/360 and audio 1440/1440 channel values bit-identical. The audio output has 198 distinct colors.
- Payload: `spike.wasm` 1,897,886 bytes raw, 499,501 gzip -9. Node glue 20,620 gzip. -O3, no size tuning.
- Not covered: Mac and Linux natives (different FFT backends may shift audio slightly), browser glue, `-Oz`, a SIMD-off build.

## Lessons
- OpenCV under Emscripten needs `-msimd128`, and its installed CMake config cannot be used for a core+imgproc build (build-toolchain.md)
