# Aurora control API (`/api/v1`)

Id: api-v1-adapters

For people writing adapters (MQTT bridge, MCP server, scripts). The contract is
[openapi.yaml](openapi.yaml) at `info.version` 1.0.0, and this page is the short
tour. Scope and reasoning: [[api-v1-plan]], [[api-v1-review]].

## Basics

- Base URL `http://<host>:8215`, paths under `/api/v1`. The WebUI's unversioned `/api/*` routes are internal and may change.
- `GET /api/v1/version` answers `{version, apiVersion}`. Key on `apiVersion`, not the app version.
- Generate clients from `openapi.yaml` (`openapi.json` is the same document, generated by `gen-openapi.py`).

## Compatibility

- Within 1.x nothing is removed or renamed. New fields, new values of `state`, `scope`, event topics and error codes can appear, so ignore what you do not know.
- Additions bump the minor (`1.1.0`), and fixes to the spec alone bump the patch.
- A breaking change would be `/api/v2`. Unknown `/api/` paths answer a JSON 404.

## Auth

- Loopback callers need no token. Other callers pair once and send `Authorization: Bearer <token>`.
- Scopes in order: `read`, `draft`, `control`, `apply`, `admin`. Each includes the ones before it.
- `PATCH /api/v1/state` needs `control`. Graph drafts need `draft`, light tests and apply need `apply`.

Pairing (RFC 8628 style, all three routes open to everyone):

- `GET /pairing/status` says whether you need a token.
- `POST /pairing/request` with `{name, scope}` returns `{pollKey, code, interval, expiresIn}`. Show `code` to the user, who approves it in Aurora. The user may grant less than asked.
- Poll `GET /pairing/request/{pollKey}` every `interval` seconds. 202 keep polling, 429 poll slower, 403 denied, 410 expired, 200 approved with the token (shown once).

## Reading state

- `GET /state` is the whole picture: `state` (`idle`, `running`, `paused`, `failed`), `effect`, `brightness` (percent), `configuredInputs`, `errors`, `conditions`.
- Brightness 0 means off only for outputs in `GET /capabilities` `zeroOffOutputs`.
- `GET /events` is one SSE stream with topics `state` and `health`. Both send a snapshot on connect and again on change, so a reconnect resyncs. Hold one stream per client, the server caps them.
- `GET /effects` lists effect ids and titles, `GET /descriptors` the control metadata.

## Writing state

One call, any subset, validated whole before anything is written:

```json
PATCH /api/v1/state
{"running": true, "effect": "builtin.video", "brightness": 60}
```

- Merge patch semantics: absent fields stay, `null` is rejected.
- Unknown fields answer `unknown_field`, read-only ones `read_only_field`, with every problem in `errors`.
- A paused host saves the effect and applies it on resume.
- A changed effect, a pause or a resume ends a running light test with `superseded`. Brightness does not.

## Errors

- Problem details (RFC 9457) plus `succeeded: false` and a snake_case `error` code. Branch on the HTTP status first and the code second, since new codes can appear.
- A failed reload still answers 200 for `PATCH /state` and shows in `errors` of the state.

## Not in 1.0

- Source selection (monitor, audio sink) arrives in 1.1 (Aurora-5ipy.44).
