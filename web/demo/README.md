# Aurora Demo: Web

A fully self-contained, zero-install browser demo of Aurora's effect —
video in, reactive lights out — running entirely client-side as a Three.js
scene. No native backend, no build step. The zero-install front door for
the project; the native app ([`app/linux`](../../app/linux)/
[`app/windows`](../../app/windows)) is the upgrade path for
anyone who wants it driving real bulbs.

Distilled from [huenicorn](https://gitlab.com/openjowelsofts/huenicorn)
(GPL-3.0) by way of [Aurora core](../../), so this repo carries the same
license forward — see `../../LICENSE`.

See [[browser-analysis]]
and [[implementation-plan-phase-3]]'s
Milestone 1 for the full scoping and reasoning behind this repo's
shape and its split from Aurora core.

## What's here

The bundled sample video now actually drives the scene: a real `<video>`
element plays `assets/168273-838673780.webm` as the plane's texture, each
frame is sampled to a small offscreen canvas, fed to the WASM graph engine
(in a Worker), and the engine's zone colors light the room live. The plane rebuilds to the video's real aspect ratio
once its metadata loads, rather than assuming exactly 16:9.

- `index.html` / `main.js` — the scene, video wiring, and per-frame sampling loop.
- `zonemap.js` — the 9-slice zone definitions, shaped to match Aurora
  core's `ZoneMapStore` JSON exactly (`zoneId`/`uvs.min`/`uvs.max`/`active`/
  `gamma`) so a real exported profile could drop in with no reshaping.
- `engine-worker.js` / `engine-host.js` / `engine-client.js` — the engine in a
  module Worker. Protocol `{id, call, args}` in, `{id, result}` out, calls named as in
  [`web/engine`](../engine/README.md), plus `batch`. `engine-room.js` feeds the graph
  what it needs each tick and reads the colors back. `vendor/fetch-engine.py` copies
  the (uncommitted) wasm module in from a CI artifact.
- `recipes/` (gitignored) — the recipes page, made by `vendor/build-recipes.py` from `web/graph-editor` and `docs/recipes`. See [[effect-recipes]].
- `graph-editor/` (gitignored) — the graph editor build, made by `vendor/build-editor.py`
  (also run by `fetch-engine.py`). The Dashboard probes it, so without the build Edit graph
  stays hidden. It opens in an iframe in the Dashboard pane (`demo-boot.js` `openEditor`),
  and `demo-editor-entry.js` runs first in the frame to install `demo-editor-frame.js`: `/api/`
  fetches and EventSources call the parent's `window.auroraDemo` `{route, streams}`.
  The editor's back link calls `window.auroraCloseEditor()`, which remounts the Dashboard.
  The editor's routes run on the room's engine (`demo-graph-routes.js`): drafts (`demo-drafts.js`),
  the preview stream (`demo-preview.js`, ticked by the room's batch), Test on lights
  (`demo-lighttest.js`, 15 s cap and 6 s heartbeat lapse as core), save, apply, duplicate, effect
  switch and custom effect tuning. Pairing routes stay 404. `demo-graph.js` now only serves
  `/api/nodes` when the engine is missing.
- `demo-effects.js` — custom effects, hidden and order in localStorage (`aurora-demo-effects`).
- `builtin-graphs.js` — the two built-in graph documents, generated by `gen-builtin-graphs.py`.
- `viz.html` + `viz.js` — the standalone light-viz page (Aurora-gj0.6): the
  room rig on the shared `scene-core.js`, no WebUI/video/audio DOM. Its color
  source is `live-data-source.js` (an `EventSource` against the relay in
  [`tools/light-viz-relay`](../../tools/light-viz-relay)), the third provider
  beside `video-source.js` / `audio-source.js` (contract documented on
  `main.js`'s `animate()`). Channel id -> `ROOM_ZONE_MAP` order is fixed
  (0/1/2/3 = front-left/front-right/back-left/back-right). The page stays dark
  until the first mappable frame, by design. Full live run: that README's
  "End-to-end viz run".
- `vendor/webui/` — a byte-identical vendored copy of `web/ui` for the
  GitHub-Pages demo (file list in `vendor/webui/MANIFEST.json`). Never
  hand-edit: fix `web/ui` and re-run `python3 web/demo/vendor/sync-webui.py`
  from the repo root; `vendor/webui/seams.test.mjs` (changed copies) and
  `vendor/webui/closure-check.mjs` (unlisted new imports) fail CI on drift.
- `assets/` — bundled sample media. See "Media credits" below.

## Running

The engine module and the editor are built output, not committed. Fetch both first
(the module is the `aurora-engine-wasm` artifact of the `wasm` CI workflow):

```
python web/demo/vendor/fetch-engine.py <dir with aurora-engine.mjs and .wasm>
python web/demo/vendor/fetch-engine.py --editor-only   # editor only
```

Then serve the repo root with any static server that sends `.mjs` as JavaScript
(Python's `http.server` sends `text/plain` on Windows, which breaks the engine import)
and open `web/demo/index.html`. Use a regular browser: VS Code's built-in browser does
not load the demo video, so Screen colors looks dead there.

Tests: `node <name>.test.mjs`, no build step.
