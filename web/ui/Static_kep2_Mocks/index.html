Effect dropdown with an attached panel (Aurora-kep2.2)

No Video/Audio toggle. An "Effect" label sits above the trigger like Monitor below it. The panel is non-modal (no scrim, closes on outside click or Esc), a labeled dialog holding an ARIA tree. Frame 9 is the working spec, frames 1-7 are static states of the same tree, and frame 8 is the rejected button-row alternative. Tooltips and row menus render in the panel outside the tree and its scroll region, under their row, flipped above it when they would leave the viewport. Built-in rows offer Edit graph, Duplicate and Hide. Hidden is a collapsed-by-default group with no count and only renders when non-empty. Every group header collapses. No row is dimmed: failures such as a missing input surface only after the click, through the shell banner (failed build) or an inline line (rejected request). The running effect has no Hide item. Rows carry no input badges. A secondary text line under the name is used only for "Built-in" on hidden built-ins.

Frame 1: built-in row menu

Fire selected. Built-in rows offer Edit graph, Duplicate and Hide. Hidden is collapsed at the bottom. The row menu sits in the panel outside the tree, under its row.

Frame 2: custom row menu, Hidden expanded

Edit graph, Unhide and Duplicate on a hidden built-in. A hidden custom row (Plasma here) also has Rename and Delete. The Hidden header is an expandable tree node (aria-expanded).

Frame 3: long list

The list scrolls inside the panel. Group headers stick within their section and the New effect footer stays pinned. The Lava lamp menu would run off the bottom, so it flips above its row. It lives outside the scroll region, so the list does not clip it.

Frame 4: groups collapsed

Every group header is an expandable tree node with the chevron on the left edge, lined up with New effect. A collapsed group that holds the selected effect shows a check at the right of its header (the trigger already names the effect).

Frame 5: description tooltip

Hovering or focusing a row shows its description (role=tooltip, linked by aria-describedby on the row). Like the row menu, it renders in the panel outside the tree and its scroll region. Touch has no hover, so the description is a supplement and nothing essential lives only in it.

Frame 6: both built-ins hidden

A group renders only when it holds a visible effect. With both built-ins hidden the Built-in header is gone and they sit under Hidden. Custom and Hidden follow the same rule.

Frame 6b: built-ins hidden and no custom effects

Only Hidden renders. Its rows can still be picked: a hidden effect may run and keeps its check inside Hidden. Only the running effect's menu drops Hide.

Frame 8: button rows (rejected, interactive)

Kept for the record: the tree in frame 9 was chosen. Same look as frame 1 with rows built as buttons (aria-current on the running effect) inside role=group. This frame works: Up/Down/Home/End move focus without switching, Enter, Space or click switches, Right and Left hop between a row and its ellipsis, Esc returns to the trigger, group headers collapse. The list is one tab stop. The trigger is named "Effect, Fire". The last action prints under the page and is announced through a live region.

Frame 9: tree (the spec, interactive)

The list is an ARIA tree: group headers are expandable nodes and effects are their children, all in one arrow sequence. Up/Down walk headers and rows. Right expands a group or steps into it, Left collapses it or steps out to its header. Enter or Space switches on a row and toggles on a header. Typing a letter jumps to a match. A treeitem cannot hold a button, so the ellipsis is mouse-only. On a row, Right opens its actions menu (like stepping into a group) and Left or Esc closes it. Shift+F10 and the Menu key do the same. The row announces that it has a menu. Hide and Unhide work and show where focus lands. The panel is one tab stop. New effect is the last item in the arrow sequence, so Down from the last row (or End) lands on it and Up returns.

Frame 7: closed

Also the success state of a switch: the label moves to the new effect only once the running pipeline confirms it, and the live region announces "Switched to Rainbow drift."

Switch states

A pick closes the panel and focus returns to the trigger. The trigger text is always what is on the lights, never the pick. The pick shows only as a status line under the trigger.

Failed build

The old effect stopped, the pick stays saved and the host is failed, so Pause is hidden. The banner names the effect and the reason, with no X. A button shows only when one click can resolve the error. Retry resends the saved config, so it helps when something can change outside Aurora, like a permission, and not when the input does not exist. The pickers follow the requested effect, as real controls only, so the default audio device sentence does not show here.

Request rejected

Nothing ran, so the old effect keeps running and the trigger already says which. An inline line gives the cause and clears once the running effect changes.

Saved but not applied shows the frame 7 look with the shell banner above. An unreachable daemon is the shell takeover. Neither adds a line here. With nothing set to run the trigger reads "No effect running" (frame 6b).

Row menu follow-on flows (Aurora-kep2.6)

What happens after each row menu item, and the menus in each gated state. Decisions are in the bead's design field.

Rename

The row's name becomes a text field holding the title, all selected, and the ellipsis goes until it closes. Enter or leaving the field saves. Esc cancels. An empty or unchanged name closes without a request. A name another effect already shows keeps the field open with a line under it. Focus returns to the row and the live region says "Renamed to X." Built-ins have no Rename.

Delete confirm

Delete replaces the row menu with a confirm in the same spot. Focus starts on Cancel, and Esc or Cancel goes back to the row. A Delete press counts only if it started on the confirm, so a double tap on the menu item cannot delete. For the running effect the confirm names the built-in that starts instead, and the delete then runs the switch states (panel closes, "Switching to Screen colors…"). Any other delete keeps the panel open, moves focus like Hide and says "X deleted."

New effect

New effect opens a Start from menu with the built-ins. Each opens the graph editor on that built-in, which already saves a built-in as a new effect. A build with only one built-in skips the menu. Starting from a custom effect is Duplicate then Edit graph, so the editor needs no new parameter.

Duplicate

The copy is titled "X (Copy)" ("X (Copy 2)", "X (Copy 3)" when taken), goes last in Custom, and never runs. The panel stays open, focus moves to the copy and it scrolls into view. It does not start a rename.

Gated menus

Gated items are left out, never shown disabled, like Hide on the running effect. Hidden custom rows carry Rename and Delete too, so Not Admin drops Delete there as well. Move up is left out on the first row of a group and Move down on the last.

Light test: the test is not a row, so no row is checked and every menu is unchanged. Menu items that never touch the running pipeline (Hide, Unhide, Move, Rename, Duplicate, Edit graph, New effect, Delete of another effect) leave the test alone. Picking a row ends it. Deleting the saved active effect underneath the test would also end it, so that row's menu leaves out Delete (frame 19b), and the shell banner's Stop test button is the way out. Keep and Revert stay with the client that started it.

Long-press

A menu opened by touch (long-press on the row or a tap on the ellipsis) starts with the description as a plain line. Mouse and keyboard keep the tooltip instead. An effect with no description has no line.
